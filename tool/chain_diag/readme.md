# 测量链路诊断（误差分解：链路 vs 模型）

回答一个问题：**「总根长 / 根数」的误差，是模型的锅，还是测量链路的锅？**

`test/test.py` 只给一个「预测 vs 真值」的差，看不出误差来源。同一个数上，
换算法、加分辨率、改损失，可能全都是在给一把错了的尺子调刻度。
本工具在同一批图上同时算多条路线，逐图对比。

## 用法

项目根目录下、`pcc` 环境：

```
python tool\chain_diag\chain_diag.py --dir datasets\root\test --no-model   # 只量链路
python tool\chain_diag\chain_diag.py --dir datasets\root\test --model model_202609192043
python tool\chain_diag\chain_diag.py --dir datasets\root\train --limit 5
```

输出：控制台表格 + `result/chain_diag/chain_diag_{时间戳}.csv`。

## 它算的四条路线

| 记号 | 输入 | 处理 |
| --- | --- | --- |
| **A** 参考 | RSML 折线 | 直接量欧氏长度（唯一的真值口径） |
| **B0** 纯链路 | GT 掩码 | 骨架 → 分链，**不剪枝、不过滤、不归一、无 ROI、无锚定** |
| **B1** 完美模型 | GT 掩码 ∩ GT 检查框 | 骨架 → 分链 → 起点锚定到 GT 茎＝**部署的完整口径** |
| **C** 当前系统 | 模型预测掩码 | 与 B1 同一条流水线 |

于是：

```
B0 − A    链路固有偏差（与模型无关，换模型也修不掉）
B1 − A    系统上限（掩码完美时还剩多少误差）
C − B1    模型的真实贡献  ←「换模型/加分辨率/改损失」能动的就是这部分
C − A     当前实际
```

## 2026-09-22 实测结论（11 张测试图，model_202609192043）

| 路线 | 总长均值 | 相对 A | 逐图绝对 |
| --- | --- | --- | --- |
| A 参考 | 30599 px | — | — |
| B0 纯链路（不剪枝） | 30026 px | **−1.9%** | 2.5% |
| + 部署剪枝（spur 45 / min_len 20） | 29551 px | −3.4% | 3.6% |
| **+ 起点锚定 = B1** | **32887 px** | **+7.5%** | **10.3%** |
| C 系统（模型 + 锚定） | 27420 px | −10.4% | 13.8% |
| C 系统（模型，**不**锚定） | 23528 px | −23.1% | 19.1% |

### 结论 1：**测量链路是直的，不用换工具**

骨架化一条 10px 宽的折线再量回来，只差 −1.9%（逐图绝对 2.5%）。
所以「总长系统性偏短」**不是链路的锅**，换 RhizoVision / RootNav / WinRHIZO 都不会更好
—— 文献里这些工具互相就差 4~7%，本项目的链码已经在最好的那一档。

另外两条**独立**的长度估计量也验证了这一点（同一批 GT 掩码）：

| 估计量 | 总偏差 | 逐图绝对 |
| --- | --- | --- |
| **骨架 8 邻域链码（本项目）** | **−1.9%** | **2.5%** |
| 面积 ÷ 平均宽度 | −10.1% | 9.7% |
| Crofton 周长反推 | −10.8% | 10.4% |

### 结论 2：**起点锚定是全系统最大的一处系统性偏差**

`B0(−1.9%) → B1(+7.5%)`，锚定单独加了 **10.9 个百分点**，把逐图绝对误差从
3.6% 放大到 10.3%（**3 倍**）。

机制：锚定是**按「条」补**的 —— 每条折线的近茎端都被补到最近的茎像素。
而实测真值折线的端点**距茎中位 27~490px**（跨图差 18 倍），
锚定却用固定阈值 `clamp(6×r_eq, 250, 600) = 600px`，**一个常数套一个变化 18 倍的东西**。

配置里原来写「标注是从茎边开始画折线…补回的长度与标注口径一致」
—— **那句是错的**，实测标注起点并不在茎边。已在 `config.py` 与
`common/skeleton_stats.py` 更正。

### 结论 3：模型确实欠分割

C 与 B1 差 **−16.6%**，这是模型的真实贡献。
分批次看：CK 批次（`root_C001-1_*`）**4/4 全在 −21% ~ −34%**，ST 批次 −4% ~ −34%
—— **CK 是明确的域偏移**，不只是随机误差。

滞回低阈值扫描进一步暴露两条独立缺陷：

| low | 总长 | 偏差 | 掩码宽度 | 根数 |
| --- | --- | --- | --- | --- |
| 纯 0.5 | 18710 | **−38.9%** | 16.1px | 44.5 |
| 0.20 | 21946 | −28.3% | 20.6px | 34.4 |
| **0.10（当前）** | 23528 | −23.1% | **23.0px** | 30.3 |
| 0.05 | 24828 | −18.9% | 25.4px | 26.6 |

- **缺陷 A：漏细根。** 干净阈值下只有 −38.9%，远端细根没检出。
- **缺陷 B：掩码偏胖。** GT 掩码宽度 **9.5px**（＝`MASK_LINE_WIDTH`），
  模型在纯 0.5 下就是 **16.1px，胖 70%**。胖掩码让相邻根粘成片 → 骨架退化成粗树 →
  **同时**让总长偏短、根数偏少。滞回阈值是在这两者之间做交易。

## ⚠️ 「根数」在这份数据上不可用

**`root_stats` 数的是 RSML 里 `<root>` 元素的个数 = 折线条数 = ID 数。**

用户的标注习惯（2026-09-22 确认）：**根系交叉之后看不出后续是哪个根**，
所以在交叉处断开、过了交叉另起一条重画 —— **一条物理根 = 多条折线 = 多个 ID**。

实测 `plant_ S068-4_20251126ST` 的 114 个 ID 里有 **75~103 个是续接**
（判据：存在另一条折线，其终点到本折线起点的距离 ≤150px 且方向夹角 <30°）。

放大图看得最清楚（`result/_rsml_zoom.png`）：一条完整的根上
**○起点 □终点 ○□○□ 交替排下去**，被切成十几段。

### 想靠后处理补救也不行

加了方向连续性约束再合并端点，结果对缺口阈值极度敏感：

| 缺口阈值 D | 20 | 40 | 80 | 150 | 250 |
| --- | --- | --- | --- | --- | --- |
| 平均根数 | 39.3 | 38.3 | 34.2 | 30.6 | 27.7 |

缺口距离分布是 **20~400px 连续、无双峰**（中位 111px）——
因为缺口宽度 = 压在上面那根根的宽度 + 标注随手留白，跨图不一样。
**没有物理依据能定阈值。**

### 能用的做法：只在「无续接片段」的图上读根数

`test/test.py` 现在会逐图输出「其中续接片段」这一列，并单独汇总：

```
根数平均绝对误差 12.91 根（只在无续接片段的 6/11 张上算: 2.50 根）
```

**6 张干净图上的 2.50 根才是有效读数**；12.91 里有一大半是标注习惯造成的。
5 张被标注撑大的图不参与根数评比。

> 另一个旁证：根数在 **26.6~44.5** 之间几乎完全由后处理阈值决定
> （见上面那张 low 扫描表），跟模型学到了什么基本无关。

**根治只能改标注规范**（交叉处不要断开，或断开但记录父子关系）。
在那之前，**根数类指标只作参考，不要当验收标准**。

## 与 `test/test.py` 的关系（2026-09-22 起）

`test.py` 的主指标已改成 **预测 vs 「理想掩码」**（＝ B1），
也就是「真值掩码走与预测逐字相同的流水线」的输出。
这样把流水线固有偏差（上面结论 2 的那 +7.5%）剔掉，剩下的才是模型的贡献。

CSV 里同时保留三个数，谁都不藏：

```
GT总长-标注(px)     ← A，原始 RSML 折线长
GT总长-理想(px)     ← B1，掩码走同一条流水线
预测总长(px)        ← C
```

`test.py` 的打印里会给出 `vs 理想掩码` 与 `vs 原始标注` 两个 MAE。

## 参数

| 参数 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- |
| `--dir` | 是 | — | 数据集目录（含 `images/` 与 `labels/roots/`） |
| `--model` | 否 | 最新 | 模型文件夹名（可省 `model_` 前缀），规则同 `test.py` |
| `--no-model` | 否 | 关 | 不算 C、不加载模型，只量链路（**秒级**，推荐先跑这个） |
| `--size` | 否 | 权重里记录的 | 模型输入长边 |
| `--mask-width` | 否 | `config.MASK_LINE_WIDTH` | GT 折线画掩码的线宽 |
| `--spur` / `--min-len` | 否 | `config` 的值 | B1/C 的剪枝与最短根阈值 |
| `--limit` | 否 | 0=全部 | 只跑前 N 张 |
| `--out` | 否 | `result/chain_diag` | 结果目录（重名自动加 `-1`） |
| `--cpu` | 否 | 关 | 强制 CPU |

## 什么时候该重跑

- **换模型**：看 C 有没有往 B1 靠。
- **改后处理参数**：B1 会跟着变，C−B1 才是可比量。
- **换数据集/新标注批次**：链路的天花板可能变（线宽、标注习惯都会变）。
- **想在链路上下工夫之前**：先确认 B0 到 A 的差有多大。本项目只有 −1.9%，
  所以链路不值得再投入；如果换成标得很细的图（比如只画 1px 中心线），结论会反过来。
