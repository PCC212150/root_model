# 标注转换的对照工具

证明「rsml → 并进 json」这一步**没有改变任何真值**。转换前后各抓一次指纹，逐样本比。

```
python tool\check_convert\check_convert.py --dir "D:\目标" -r --capture before.json   # 转换前
python tool\check_convert\check_convert.py --dir "D:\目标" -r --compare before.json   # 转换后
```

## 比什么

| 项 | 说明 |
| --- | --- |
| 折线数 / 点数 | |
| **坐标序列 sha256** | 按序把每个坐标 `struct.pack('<d')` 后哈希 —— **逐位敏感**，不是近似比较 |
| 原图分辨率掩码 sha256 | 用 `common/gt_mask` 的画线原语画出来再哈希 |
| 图片实际尺寸 vs json 记的尺寸 | 图片尺寸**只读文件头拿**，不信 json 里写的那个字段 |
| 顶层键与键序 | |
| stem / check 的条数 | root 那一类**故意**要从 0 变成 N，所以不参与相等比较，只作信息报告 |

差异会报到**具体位置**：

```
❌ root_C001-1_20241229CK  ← C\root_C001-1_20241229CK.json
     coords_sha256:  '3082ac82…'  →  'a41f9c03…'
     第一处坐标不同: 第 7 条折线 / 第 12 点:  (1234.5, 678.9)  →  (1234.5, 679.1)
```

坐标哈希对不上时，`first_diff` 会告诉你第一条是哪条、第一个点是哪个点、两侧各是什么 ——
「哈希不同」本身没法查。

## ★ 为什么还要看「来源」

加载器支持新格式之后是这么工作的：**json 里有 root 就用 json，否则退回 `.rsml`。**

这个回退很方便，但它会让上面那一整套比对**变成空转** ——
如果转换根本没跑，加载器会退回 rsml，新路径**就是**旧路径，
于是「逐位相同」完美通过，而数据一个字节都没变。**比对双方其实是同一份数据。**

所以工具会在两处独立把关：

1. `--compare` 结束时检查：**转换前有根可转、转换后却仍从 rsml 读**的样本，一律判失败。
   （判据是「转换前的折线数 > 0」，不是「json 里有没有 root」——
   像 `plant_S003-3` 那种 rsml 里本来就 0 条根的合法负样本，没东西可插，不该被算成漏转。）

2. `--provenance`：直接问加载器「这张图实际用的是哪个来源」。
   这是**唯一允许引用新 API** 的模式 —— 「来源」这件事本来就只有加载器知道。

```
python tool\check_convert\check_convert.py --dir "datasets\root\train" --dir "datasets\root\test" --provenance
```

## 为什么自己读文件、不走项目的加载代码

`common/dataset.py` 的加载器**正是被验证的对象之一**。拿它来算「转换前」，
等于用被测对象给自己出题。

所以这里只借三样**不受转换影响**的东西：`common.rsml_parse.parse_rsml`
（旧格式的权威读法）、`common.gt_mask` 的画线原语、`config.py` 的常量。

## 参数

| 参数 | 说明 |
| --- | --- |
| `--dir` | 目标文件夹，**可重复**。既认扁平布局（三件套同目录），也认 `labels/other` + `labels/roots` + `images` 的项目布局 |
| `-r` / `--recursive` | 递归子文件夹 |
| `--roots-from` | `auto`（默认）= json 里有 root 就用 json，否则退回 rsml；`rsml` = 一律读 `.rsml` |
| `--capture FILE` | 逐样本指纹写到 FILE |
| `--compare FILE` | 与之前抓的指纹比对 |
| `--no-mask` | 跳过掩码哈希（快得多；坐标逐位相同则掩码必然相同） |
| `--provenance` | 断言加载器实际用的是 json 来源 |

**转换前后都用默认的 `auto`。** 转换前那批会落到 rsml、转换后落到 json，正好是要比的两侧；
而且结束时那条「有没有漏转」的检查才会生效。

指纹文件里存了**完整的折线坐标**，不只是哈希 —— 一是比对时要靠它定位第一处不同，
二是 `datasets/` 不入 git、源数据又只有一份，指纹本身就是那份留存的证据。
