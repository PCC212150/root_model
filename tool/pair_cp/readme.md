# 裁掉 C/P 无法成对的图片（为实现对照）

C（`<前缀>_C###-#_<日期>CK.jpg`）与 P（`<前缀>_P###-#_<日期>PEG.jpg`）是两个处理。
做对照实验，要求**同一个「编号-重复-日期」两边各有一张**。实际数据里有三类坑：

| 情况 | 例子 | 处理 |
| --- | --- | --- |
| **前缀不对** | 数据是 `plant_` 命名，却按 `root_` 去匹配 | 整批误判 —— 见下面「前缀与文件夹名」 |
| **异常命名** | `root_P137-1 (2)_20250108PEG.jpg`（带 `(N)` 标记） | 剔除 |
| **单边缺某天** | C 缺 `20250106`、P 缺 `20250110` | **两边都剔除** |

规则**纯按文件名**，不改名、不按图像内容猜归属：

```
异常命名的        -> 剔除
两边都有的日期     -> 保留
只有一边有的日期   -> 两边都剔除（保证严格一一对应）
非图片文件        -> 不碰（.rsml/.json 标注原地保留）
```

## 非图片文件不在裁剪范围内

只有 `IMAGE_EXTS`（jpg/jpeg/png/bmp/tif/tiff）里的文件才进配对流程，
`.rsml` / `.json` 等标注**一律跳过、原地不动**，只在报告里数一个数。

2026-09-19 之前不是这样：那时所有不符合 jpg 命名的文件都算「异常命名」，
所以旧 `C\` 里那 4 个 `root_C001-1_*.rsml` 会被当成异常图片扫进隔离目录 ——
**标注文件被搬走比图片被搬走更隐蔽**，因为图片少了看得出来，标注少了往往要等
训练报错才发现。

## 前缀与文件夹名：两处不能想当然

2026-09-19 踩到过，两处都会让**全部文件**被误判成「异常命名」：

1. **文件名前缀换过**（`root_` → `plant_`）。正则写死 `root_` 的话，`plant_` 那批
   一个都匹配不上。现在前缀默认**从数据里自动探测**（取出现最多的那个），
   也可以用 `--prefix` 显式指定。
2. **文件夹名不再等于侧别字母**（`C`/`P` → `C_plant`/`P_plant`）。旧代码拿文件夹名
   直接和文件名里的字母比，改名后永远比不中。现在从文件夹名里取**第一个大写
   C 或 P** 作为侧别（`C_plant` -> C、`plant_P` -> P，小写的 p 不会误认）。

另有一道防呆：单次要剔除的文件**超过总数一半**时直接罢工、不动任何文件，
除非加 `--force`。正常数据只剔零星几个，触发它几乎一定是上面两处配错了。

## 用法

```
python tool\pair_cp\pair_cp.py --dir "E:\baiduwangpan\DownLoad" --dry-run   # 先预览
python tool\pair_cp\pair_cp.py --dir "E:\baiduwangpan\DownLoad"             # 正式执行
python tool\pair_cp\pair_cp.py --dir "..." --quarantine "D:\回收"           # 指定隔离目录

# plant_ 命名、文件夹带后缀的一批（2026-09-18 重新导出的那份）
python tool\pair_cp\pair_cp.py --dir "E:\baiduwangpan\DownLoad" ^
    --sides "C_plant,P_plant" --quarantine "E:\baiduwangpan\DownLoad\_剔除_CP对照_plant_20260919" ^
    --log "E:\baiduwangpan\DownLoad\CP对照_剔除日志_plant_20260919.csv"
```

| 参数 | 说明 |
| --- | --- |
| `--dir` | 含两侧子文件夹的父目录（**必填**） |
| `--sides` | 两侧文件夹名，逗号分隔（默认 `C,P`） |
| `--prefix` | 文件名前缀（如 `root` / `plant`）。**默认自动探测** |
| `--quarantine` | 剔除文件的去处，默认 `<dir>\_剔除_CP对照\` |
| `--log` | 日志路径，默认 `<dir>\CP对照_剔除日志.csv`。**重跑时换个名字，别盖掉上次的记录** |
| `--force` | 剔除比例超 50% 也照做（默认罢工） |
| `--dry-run` | 只报告要剔除哪些，不动文件、不写日志 |

## 剔除的文件是「移走」不是「删除」

移到 `<dir>\_剔除_CP对照\<C|P>\` 里**原样未改**，配合日志可以随时搬回来。
确认无误后自行删掉隔离目录即可。重复执行是幂等的（裁完再跑一次是 0 个可剔）。

执行后在 `--dir` 下生成日志（UTF-8 BOM，Excel 直接打开），逐条记录
「侧 / 文件名 / 编号-重复 / 日期 / 剔除原因 / 隔离位置」，表头前有 5 行
`#` 注释写清本次的规则、保留数、剔除数与隔离目录。

## 实测

### 第二次：`plant_` 命名（2026-09-19，源为 09-18 重新导出）

```
前缀：自动探测到 plant_
C_plant（C 侧）: 标准命名 6488 / 异常 0
P_plant（P 侧）: 标准命名 6485 / 异常 4
两边都有（可对照）: 6477     C 独有: 11     P 独有: 8
剔除 23 个 -> C 剩 6477 / P 剩 6477   差集 0 / 0  严格一一对应
```

剔除的 23 个分三类：

- **异常命名 4 个**：`plant_P137-1 (1)/(3)/(5)/(7)_20250108PEG.jpg`；
- **C 独有 11 个**：137-1/2/3/4 的 `20250108`、148-2/3/4 与 192-1..4 的 `20250110`；
- **P 独有 8 个**：013 与 091 的 `20250106`。

> **比上一版修好的两处**：`179@20250106`（上次 P 独有）和 `148-1@20250110`
> （上次 C 独有）这一版两边都齐了，不再是问题。

> **`C137-*@20250108` 仍是被连累的**：C 侧 4 张完全正常，剔除它们是因为 P 侧
> 那天的文件全被导出成了 `plant_P137-1 (N)_20250108PEG.jpg`。按「异常命名先剔除、
> 再保留两边都有的日期」的规则，这对自然配不上。
> ⚠️ **上次 readme 里那条「图像比对：(8)→137-1、(6)→137-2、(4)→137-3、(2)→137-4」
> 对这批新文件不成立** —— 已核对 md5，本次 4 个 `(1)(3)(5)/(7)` 与上次 4 个
> `(2)(4)(6)(8)` 内容**两两不同，是 8 张不同的图**。要救这 4 对，得基于本次这 4 个
> 文件重做一次图像比对再改名（工具本身不猜归属）。
>
> **2026-09-19 决定：不救。** 这 4 对（C137-1/2/3/4 @20250108）不计入 C/P 对照分析。
